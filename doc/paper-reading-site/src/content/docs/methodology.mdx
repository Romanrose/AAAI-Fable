本页描述项目当前用于实验的结构映射方法。它服务于“课程知识如何变成寓言逻辑”这一步，位于知识图谱/机制建模之后、故事正文生成之前。

这里的主张是：**寓言映射首先是一个可验证的结构计划，而不是一次自由写作。** LLM 的职责是提出语义上连贯的候选故事域；是否接受候选，则由机制图覆盖、关系方向、术语泄漏和模板风险等显式条件决定。

> 方法状态：当前实现为 `llm-guided-copycat-mvp/v1`。它是 Copycat 启发的实验方法，不是对经典 Copycat 的完整复现，也不是已完成的大规模效果结论。

## 输入与边界

结构映射从已审核的 `MechanismGraph` 开始，而不是直接从教材段落或一个概念名称开始。其上游已经完成目标概念定位、图检索、机制提取、验证和人工审核；映射阶段读取的上下文由目标概念、检索证据、机制节点与边、以及生成约束组成。

它的输出也不是故事正文，而是一个 `Mapping Plan`：

- 每个机制节点对应一个具体的故事载体（`story_carrier`）；
- 每条机制边对应一个可区分的故事关系（`story_relation`）；
- 每条边必须记录 `direction_preserved: true`；
- 计划还必须包含故事域、冲突、事件链、转折点与解决状态。

因此，故事写作与结构映射被故意分开：生成器只应接受已经通过映射检查的计划。

## 映射流程

```text
Approved MechanismGraph + retrieval context
        │
        ▼
LLM semantic scout
  └─ 一次调用，返回恰好 3 个中文寓言映射候选
        │
        ▼
确定性验证与评分
  ├─ 节点/边全覆盖、标识符合法、边方向保持
  ├─ 禁用术语泄漏检查
  └─ 覆盖度、载体多样性、关系多样性、叙事完整性、模板风险
        │
        ▼
meta-monitor（仅有模板风险时）
  └─ 最多 1 次保持深层结构不变的受约束修订
        │
        ▼
Validated selected Mapping Plan + 完整候选与评分轨迹
```

### 1. Semantic scout：候选而非正文

`semantic-scout/v1` 要求 LLM 一次返回 **3 个**候选映射，而不是写出寓言正文。每个候选必须使用不同的故事域，覆盖所有机制节点和边，并避免使用目标概念、别名和其他禁用术语。

这一步让 LLM 承担其擅长的语义发散：提出可能的故事世界、角色、冲突与事件链；但不让它单独决定什么算是忠实映射。

### 2. 硬约束：先排除不可解释映射

候选在进入排序前必须满足以下条件：

- `node_mappings` 覆盖机制图的全部节点；
- `edge_mappings` 覆盖机制图的全部边；
- 不得引用未知节点或边标识符；
- 每条关系的 `direction_preserved` 必须为 `true`；
- 必须提供非空故事域。

验证失败的候选不会被当成一个“创意但可用”的方案。当前实现会显著降低其分数；最终胜者若仍未通过验证，整个映射任务明确失败，而不是由下游故事生成器悄悄补全。

### 3. 排序：结构保真优先于表面新颖

通过验证的候选按下表的确定性评分进行排序。权重来自当前 `scoring.py` 的实际实现。

| 信号 | 权重 | 含义 |
|---|---:|---|
| 机制节点覆盖 | 0.28 | 每个可保留机制节点都获得故事侧载体。 |
| 机制边覆盖 | 0.28 | 每个关系都获得可追踪的故事侧关系。 |
| 载体多样性 | 0.14 | 避免多个概念被压扁成同一泛化角色。 |
| 关系多样性 | 0.10 | 避免不同因果/条件关系套用同一句式。 |
| 禁用术语无泄漏 | 0.08 | 故事侧不直接说出目标概念或其别名。 |
| 叙事骨架完整性 | 0.06 | 有冲突、事件链、转折与解决状态。 |
| 模板质量 | 0.06 | 根据重复和占位符风险给予惩罚。 |

总分还会按每个模板风险额外扣减 `0.06`。实现中报告的 `temperature = 100 × (1 − score)` 是一个**不确定性诊断量**：结构越完整、越少模板化，温度越低；它不等同于 LLM API 的采样温度。

### 4. Meta-monitor：有限、保守的修订

当胜出候选出现下列风险时，`meta-monitor-refiner/v1` 最多发起一次修订：

- 重复故事载体；
- 重复关系实现；
- 重复事件；
- “第 2 道环节”等序数占位符；
- 事件变化不足。

修订时不得改变候选 ID、故事域、任何机制节点/边 ID 或边方向，也不得增删深层机制结构。只有修订后仍通过验证且分数不低于原候选时，修订版才会被接受。

## 与经典 Copycat 的关系

经典 Copycat 的关键思想是：类比取决于对象在局部结构中扮演的角色，候选解释在多种压力下竞争，概念允许随上下文发生受限滑动。本项目继承的是这种“**角色优先、候选竞争、结构约束**”的思想，而不是字面对象匹配。

当前 MVP 与完整 Copycat 仍有清楚边界：

- 没有概率式 `coderack` 调度；
- 没有随情境动态调整的 `slipnet`；
- 没有多个相互竞争的 `workspace` 结构；
- 没有非单调的温度反馈循环；
- 当前分数是结构门控与轻量词汇多样性信号，尚不是经人类标定的语义类比质量量表。

因此，确定性 Copycat 路线仍保留为对照策略；LLM-Guided Copycat 是当前主实验中用于产生更具语义连贯性的映射候选的结构映射路径。

## 可审计产物

每次运行保存下列中间产物，保证映射结论可以复查：

- `mapping_context.json`：目标概念、检索信息、机制图和生成约束；
- `candidate_evaluations.json`：全部候选、分数、模板风险与验证错误；
- `selected_mapping_plan.json`：最终选中的映射计划；
- `run_result.json`：候选数、选中 ID、模型身份、prompt 哈希和修订轨迹。

这一设计使下游评测可以追问：“故事的某一情节对应哪个机制节点或关系？”而不是只给出一个看似合理的寓言文本。
